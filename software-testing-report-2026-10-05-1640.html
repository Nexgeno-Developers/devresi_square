15. Final status

Not Ready for Production

The second pass saved a tenancy on the server, created a second property, invited and revoked a person, stored an EICR and a shared document the tenant could download, recorded a bank payment, voided an invoice, accepted a tenant repair, showed a calendar event to the tenant, saved right to rent and a notice, updated the tenant profile, and declined a rent correction without changing the £1,250 rent. Landlord contact, property manager, and estate owner reached their own workspaces. Opening another account’s property or invoice returned 403.

What must be fixed before a public release: orphan memberships must not lock a valid account out (BUG-001); the tenancy edit button must save without a property manager (BUG-002); the Landlord Basic description must match the limit of 5 properties (BUG-003); bank details must show on an open tenant invoice when they are saved (BUG-004); the rent webhook secret must be set (BUG-009); debug must be off outside local machines (BUG-010).

No Critical defect blocked a core flow after the orphan staging rows were removed. High issues remain, so this build is not production-ready. The contractor still lands on a tenant-only page. Public robots.txt blocks crawlers and there is no sitemap.

16. Testing limitations

  • Stripe sandbox was intentional. Checkout was completed with the public test card. Live mode was not used.
  • The first landlord login failed until orphan staging memberships were deleted. Results after that point use the repaired local rows.
  • The staging seeder was run on this local database before the walkthrough. It created Staging Landlord Account and related rows.
  • Invite, revoke, an EICR upload, a shared document, a bank payment, a void, a second property, a tenant repair, a calendar event, right to rent, a notice, profile changes, and a correction rejection were submitted on the staging landlord account.
  • Mail delivery was not confirmed. A password reset token exists for the invitee. The queue connection is sync. Backups were not run.
  • A signed rent webhook was not sent because the rent webhook secret is empty. An unsigned post returned 400.
  • No Firefox, Edge, Safari, Android, iPhone, or tablet device was used. Mobile coverage is still one emulated Chrome viewport of the tenant rent page.
  • No timing, query, or asset-size measurements were taken.
  • The public homepage, robots.txt, and sitemap were fetched. Open Graph was not checked.
  • A separate live landlord account exists in this database and was not logged into.
